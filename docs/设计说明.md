# 鲜花订购与管理系统 · 设计说明

> 毕业设计（论文）配套文档 · 广东交通职业技术学院 软件技术专业
> 依据《任务书：鲜花销售系统》编写

---

## 1 项目概述

### 1.1 设计背景

随着人们生活水平提高，鲜花逐渐成为表达情感、庆祝节日、商务往来中的常见礼品。
传统花店受营业时间、门店位置限制，顾客需要到店挑选，节日高峰期还容易缺货；
而鲜花保质期短、对配送时效要求高，线上化既能扩大客源，也能通过"预订 + 同城配送"提升体验。

### 1.2 设计目标

按任务书要求，模拟网上花店的销售业务，构建一个**鲜花浏览、预订、销售、购买、添加、删除、修改和库存管理**的系统：

- 用户端（两个客户端）：小程序版 + 网页版，实现注册登录、选购鲜花、订购鲜花，界面友好、温馨、方便；
- 管理端：实现鲜花添加删除、鲜花信息修改、类目与库存维护、会员管理、订单发货，
  做到易扩展、及时更新、易维护。

### 1.3 交付物

| 交付物 | 形式 |
| --- | --- |
| 设计论文 | 本设计说明 + 需求/数据库/测试章节 |
| 源程序电子文档 | `backend`（后端）、`frontend/litemall-admin`（管理端）、`frontend/flower-web`（网页版）、`frontend/litemall-wx`（小程序） |
| 作品 | 可运行的后台 + 网页版商城 + 小程序商城 |

## 2 需求分析

### 2.1 用户角色

| 角色 | 说明 | 主要操作 |
| --- | --- | --- |
| 顾客（会员） | 购买鲜花的普通用户 | 浏览、搜索、加购、下单、支付、查看订单、管理地址、领券 |
| 商城管理员 | 维护鲜花与类目 | 添加/修改/删除鲜花、上下架、改价改库存、处理评价 |
| 订单管理员 | 处理订单 | 查询订单、发货、退款、导出 |
| 超级管理员 | 系统维护 | 会员管理、角色权限、广告/优惠券/专题、系统配置、统计报表 |

### 2.2 功能需求

**用户端**

1. 注册登录：账号密码登录、退出，登录态保持（JWT，7 天）；
2. 鲜花浏览：首页轮播、类目入口、人气鲜花、本周新花、花艺品牌、花艺专题、分类楼层；
3. 分类与搜索：一级/二级类目树、关键词搜索、按新品/热销筛选、价格与时间排序、分页；
4. 鲜花详情：多图浏览、价格与划线价、规格选择（标准/豪华/尊享，各自价格与库存）、数量、
   花语详情、商品参数（花材/包装/适用场景/花期/产地）、用户评价、相关推荐；
5. 购物车：勾选、增减数量、删除、金额合计、满 99 元免运费提示；
6. 下单结算：收货地址（新增/选择/默认）、鲜花清单、优惠券选择、订单备注（期望送达时间、贺卡内容）、
   运费与优惠计算、提交订单；
7. 订单管理：待付款/待发货/待收货/待评价筛选、订单详情、支付（演示环境模拟支付）、取消、确认收货、删除；
8. 会员中心：订单数量看板、地址管理、我的优惠券、退出登录。

**管理端**

1. 数据看板：会员数、鲜花数、规格库存数、订单数；
2. 鲜花管理：检索、添加、编辑（价格/库存/类目/品牌/图片/富文本详情）、上架下架、批量删除、评价管理；
3. 类目管理：一级/二级类目树、排序、图标、楼层展示；
4. 库存管理：每个规格货品的库存数量可查可改，下单自动扣减，库存不足时禁止下单；
5. 会员管理：会员列表、详情、消费统计、收藏/足迹；
6. 订单管理：多条件查询、详情、**发货（快递公司 + 单号）**、退款、删除、导出 Excel；
7. 营销管理：轮播广告、优惠券（满减券、新人券）、专题、拼团规则；
8. 系统管理：管理员与角色权限、操作日志、对象存储、通知；
9. 系统配置：商城名称/地址/电话、运费规则、订单超时时间、小程序配置；
10. 统计报表：会员、订单、鲜花三个维度的统计。

### 2.3 非功能需求

| 需求 | 设计对策 |
| --- | --- |
| 界面有吸引力、友好、温馨 | 玫瑰粉主色（#c2456a）+ 奶油底色的花艺配色；手绘风格花束插画；卡片式布局、圆角、阴影；移动端底部导航 |
| 实用性 | 同城 2 小时送达、满 99 免运费、优惠券自动抵扣、花语与养护说明、参数表 |
| 易扩展 | 前后端分离，接口按业务域拆分；商品/类目/规格三层模型，新增类目或规格无需改代码 |
| 及时更新 | 首页、类目、广告、优惠券均可在后台配置；首页数据带本地缓存，支持 `/wx/home/cache?key=litemall_cache` 主动刷新 |
| 易维护 | 分层（controller/service/mapper）、统一响应体 `{errno, errmsg, data}`、统一异常处理、操作日志 |

## 3 系统设计

### 3.1 总体架构

```
┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐
│  微信小程序版    │   │    网页版商城    │   │    管理后台      │
│ litemall-wx     │   │  flower-web     │   │ litemall-admin  │
│ 原生 + Vant     │   │ 原生 JS SPA     │   │ Vue + Element   │
└────────┬────────┘   └────────┬────────┘   └────────┬────────┘
         │  /wx/**  (JWT)      │  /wx/**             │  /admin/** (Shiro)
         └───────────┬─────────┘                     │
                     ▼                               ▼
        ┌──────────────────────────────────────────────────┐
        │            Spring Boot 后端（8081）               │
        │  litemall-wx-api   litemall-admin-api            │
        │  litemall-core（工具/存储/支付/短信）             │
        │  litemall-db（domain/dao/service）               │
        │  静态资源：/（后台） /web/（网页版） /flower/（图片）│
        └───────────────────────┬──────────────────────────┘
                                ▼
                        ┌───────────────┐
                        │  MySQL 5.7    │
                        │  litemall 库  │
                        └───────────────┘
```

- 前后端分离：客户端只通过 HTTP + JSON 交互，两端共用 `/wx/**` 接口；
- 单端口部署：后端同时提供接口与三个静态资源目录，避免跨域，方便演示与答辩；
- 鉴权分离：客户端用 JWT（`X-Litemall-Token`），管理端用 Shiro Session（`X-Litemall-Admin-Token`）。

│   ├── 商品模块        类目树 / 列表筛选排序 / 搜索 / 详情 / 规格选择 / 评价
│   ├── 交易模块        购物车 / 结算 / 下单 / 模拟支付 / 订单状态流转
│   ├── 会员模块        登录 / 会员中心 / 收货地址 / 优惠券
│   └── 内容模块        花店介绍 / 配送说明 / 鲜花养护 / 常见问题
└── 管理端
    ├── 数据看板
    ├── 鲜花管理        列表 / 添加 / 编辑 / 上下架 / 删除 / 评价
    ├── 类目与品牌
    ├── 库存管理        规格货品库存
    ├── 订单管理        查询 / 发货 / 退款 / 删除 / 导出
    ├── 会员管理
    ├── 营销推广        轮播 / 优惠券 / 专题 / 拼团

### 3.3 核心业务流程

**（1）下单流程**

```
浏览鲜花 → 选择规格与数量 → 加入购物车 / 立即购买
   → 结算页（收货地址 + 优惠券 + 备注）
   → 提交订单（校验库存、扣减库存、生成订单与明细、清空购物车、发放订单号）
   → 待付款（30 分钟未付自动取消）
   → 支付成功（演示环境调用 /wx/order/mockpay 模拟微信支付回调）
   → 待发货 → 管理员发货（快递公司 + 单号）→ 待收货 → 确认收货 → 待评价 → 完成
```

**（2）发货流程（订单发送）**

```
管理员登录 → 订单管理 → 筛选"待发货" → 点击发货
   → 填写快递公司 + 快递单号 → 订单状态 201 → 301
   → 用户端订单详情显示"已发货"与物流信息
```

**（3）库存管理流程**

```
后台添加/编辑鲜花时，为每个规格（标准/豪华/尊享）设置库存
   → 用户下单：校验库存 → 扣减库存（SQL 条件更新，防止超卖）
   → 库存不足：返回"库存不足"错误码，禁止下单
   → 后台可随时调整库存；下架后客户端不可购买
```

**（4）订单状态机**

| 状态值 | 含义 | 可执行操作 |
| --- | --- | --- |
| 101 | 未付款 | 支付、取消 |
| 102 / 103 | 用户取消 / 超时取消 | 删除 |
| 201 | 已付款（待发货） | 管理员发货、用户退款 |
| 301 | 已发货（待收货） | 用户确认收货 |
| 401 | 已收货（待评价） | 评价 |
| 402 | 已完成 | — |

## 5 接口设计

### 5.1 统一约定

- 请求：`Content-Type: application/json`；GET 用 query，POST 用 body。
- 响应：`{ "errno": 0, "errmsg": "成功", "data": ... }`；
  `errno=0` 成功，`401` 参数不对，`402` 参数值不对，`501` 未登录，`7xx` 业务错误。
- 鉴权：
  - 客户端：`POST /wx/auth/login` 返回 JWT，后续请求头 `X-Litemall-Token`；
  - 管理端：`POST /admin/auth/login` 返回 token，后续请求头 `X-Litemall-Admin-Token`。

### 5.2 核心接口

| 功能 | 方法与路径 | 主要参数 |
| --- | --- | --- |
| 首页数据 | `GET /wx/home/index` | — |
| 类目树 | `GET /wx/catalog/index` / `all` | id |
| 鲜花列表 | `GET /wx/goods/list` | categoryId, brandId, keyword, isNew, isHot, page, limit, sort, order |
| 鲜花详情 | `GET /wx/goods/detail` | id（返回 info、specificationList、productList、attribute、issue、comment） |
| 加入购物车 | `POST /wx/cart/add` | goodsId, productId, number |
| 立即购买 | `POST /wx/cart/fastadd` | goodsId, productId, number → 返回 cartId |
| 购物车 | `GET /wx/cart/index` | — |
| 修改数量 / 勾选 / 删除 | `POST /wx/cart/update` / `checked` / `delete` | id, goodsId, productId, number；productIds；productIds |
| 结算信息 | `GET /wx/cart/checkout` | cartId, addressId, couponId, userCouponId |
| 提交订单 | `POST /wx/order/submit` | cartId, addressId, couponId, userCouponId, message → `{orderId}` |
| 模拟支付 | `POST /wx/order/mockpay` | orderId |
| 订单列表/详情 | `GET /wx/order/list`、`/wx/order/detail` | showType, page, limit；orderId |
| 取消/确认/删除 | `POST /wx/order/cancel` / `confirm` / `delete` | orderId |
| 收货地址 | `GET /wx/address/list`、`POST /wx/address/save`、`/delete` | id, name, tel, province, city, county, areaCode, addressDetail, isDefault |
| 领券/我的券 | `POST /wx/coupon/receive`、`GET /wx/coupon/list` / `mylist` | couponId；status, page, limit |
| 后台发货 | `POST /admin/order/ship` | orderId, shipChannel, shipSn |
| 后台鲜花维护 | `POST /admin/goods/create` / `update` / `delete` | 鲜花、规格、货品、参数等 |

### 6.2 页面结构（网页版）

- 顶部：logo + 域名（花语鲜花商城）+ 主导航（首页/全部鲜花/优惠券/花店介绍）+ 搜索框 + 购物车角标 + 我的；

  花艺品牌 → 花艺专题 → 分类楼层；

- 详情：左图（主图 + 缩略图）右信息（价格、规格、数量、按钮）+ 三个 Tab（花语详情/商品参数/用户评价）+ 看了又看；

- 我的：玫瑰粉渐变头部 + 订单四宫格 + 功能入口。

### 6.3 响应式

- `>1000px`：4 列商品、左侧类目栏固定；
- `641–1000px`：3 列商品、类目改为横向滚动条；
- `<=640px`：2 列商品、顶部只保留 logo + 搜索、底部固定导航（首页/分类/购物车/订单/我的）。

## 7 关键实现说明

### 7.1 规格与库存模型

鲜花 → 规格（规格名 "规格" + 值 标准版/豪华版/尊享版）→ 货品（唯一确定价格与库存）。
`litemall_goods_product.specifications` 用 JSON 数组保存所选规格值，如 `["标准版"]`，
客户端按选中规格匹配货品 ID 后加入购物车；下单时在数据库中做条件扣减，避免超卖。

### 7.2 优惠券计算

结算时遍历会员未使用优惠券，按订单金额与券门槛判断可用性，自动选出抵扣最大的一张；
用户可在结算页手动改选或不用券（`couponId=-1`）。运费规则：满 99 元免运费，否则 12 元。

### 7.3 模拟支付

微信支付依赖商户号、证书与回调地址，本地无法联调。为完整演示订单流转，
后端新增 `POST /wx/order/mockpay`：校验订单归属与状态后，将 101（未付款）置为 201（已付款），
写入支付时间与 `payId=MOCK...`，并移除超时取消任务。生产环境应改用 `prepay` + 支付回调。

### 7.4 静态资源组织

`litemall-all` 通过三个 `maven-resources-plugin` 执行，把**管理后台 dist**、**网页版静态站点**、
**鲜花图片**分别复制到 `static/`、`static/web/`、`static/flower/`，随 jar 一起发布，
因此只需启动一个进程即可演示三个端；`WebPageController` 负责 `/web` → `/web/index.html` 的跳转。

## 9 总结与展望

本项目按任务书完成了鲜花订购与管理系统的设计与实现：管理端具备鲜花、类目、库存、订单、会员、
营销、系统配置等完整管理能力；客户端提供**微信小程序版**与**网页版**两套界面，功能对齐，
数据同源；系统采用前后端分离架构，接口规范、层次清晰，便于后续扩展。

后续可优化的方向：

1. 接入真实微信支付与短信验证码，完善注册、找回密码流程；
2. 增加鲜花预订的"定时送达"与"配送范围/时段"校验；
3. 加入花艺师预约、鲜花订阅（周期送）、评价晒图与社区内容；
4. 引入 Redis 缓存首页与类目、Elasticsearch 提升搜索体验；
5. 补充单元测试与接口自动化（JUnit + MockMvc）并接入 CI。
